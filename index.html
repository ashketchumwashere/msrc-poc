🔍 Root Cause — 3 Independent Findings

#File : LineBugSecurity Boundary
1 mcpRegistry.ts:231 PROFILE-scope MCP servers skip workspace trust check — collection.scope === StorageScope.WORKSPACE is false for protocol-handler installs, so the guard never runs. VS Code spawns node -e <code> (local subprocess) in an explicitly untrusted workspace. VS Code Workspace Trust
2 urlService.ts:56 RelayURLService.open() handles vscode: URIs without checking options.allowCommands — called from mcpElicitationService.ts:222 as open(url, {allowCommands:false}) allowCommands control
3 chatContentMarkdownRenderer.ts:108 vscode: in allowedLinkSchemes — MCP tool results render vscode:mcp/install?… as a clickable blue link in Copilot chat without warning Copilot content isolation

🔧 One-Line Fix (Finding 1)

// mcpRegistry.ts:231 — BEFORE (only checks WORKSPACE-scope):
if (collection.scope === StorageScope.WORKSPACE && !isWorkspaceTrusted()) return false;

// AFTER (check trust for ALL servers regardless of storage scope):
if (!isWorkspaceTrusted()) return false;
