VS Code Workspace Trust Bypass Important

Researcher: Ashish Dhone <ashisharundhone@gmail.com>  ·  MSRC Bug Bounty  ·  3 Findings

Phase 1 — Install MCP Server

Click the button. Browser asks "Open VS Code?" → click Open. VS Code shows install UI → click Install.

▶ Install MCP Server (type:local)

Installs a type:"local" server — VS Code spawns node -e <code> on your machine.
Evidence: http://95.111.224.167:8085/logs

Reproduction Steps

Install the MCP server 2 clicks Click "Install MCP Server" above → Open → Install.
Written to ~/.config/Code/User/mcp.json at StorageScope.PROFILE.
Open an untrusted workspace critical 
mkdir /tmp/msrc-untrusted && code /tmp/msrc-untrusted
At the Workspace Trust dialog → click "Don't Trust". Status bar shows "Restricted Mode".
Open Copilot chat — subprocess spawns Press Ctrl+Alt+I → type anything → Enter.
VS Code auto-starts the MCP server and executes node -e <code> on your machine despite "Don't Trust".
Verify evidence 
cat /tmp/MSRC-WS-TRUST-BYPASS.txt
Remote: http://95.111.224.167:8085/logs — beacon from victim's node process appears.

Root Cause

#FileBug
1 mcpRegistry.ts:231 Trust check gated on StorageScope.WORKSPACE — protocol-handler installs use PROFILE scope, skipping it entirely
2 urlService.ts:56 RelayURLService.open() ignores allowCommands:false for vscode: URIs
3 chatContentMarkdownRenderer.ts:108 vscode: in allowedLinkSchemes renders install links in Copilot chat output

Fix: mcpRegistry.ts:231 — remove collection.scope === StorageScope.WORKSPACE &&
